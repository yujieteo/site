# Add a note

Every note lives in the single file `data/notes.md`; never split it into other files. Two branches that edit it can conflict (see [docs/architecture.md](../../docs/architecture.md)), so land notes changes one at a time.

1. Judgment: choose the note's tags. Inspect `data/note-tags.json` and reuse canonical tags whose descriptions fit, without redundant tags. Find related notes with [Search notes](search-notes.md) when unsure.
2. Judgment: add a canonical tag only when it names a genuinely distinct recurring topic, project, status, or action. Add its class, selection description, aliases, and `replaced_by` value to the registry in the same change. A `math.*` tag must be an offline arXiv mathematics category listed by the registry. Tag names are lowercase and can contain letters, numbers, underscores, hyphens, and dots.
3. Run `.venv/bin/python scripts/add_note.py --date YYYY-MM-DD --text "<one paragraph>" --tag <tag> [--tag <tag> ...]` (`--text -` reads the note from stdin; the date defaults to today). It puts the note at the top of its `## YYYY-MM-DD` section, inserts a missing date heading in descending date order without duplicating one, writes the tags last, and replaces an alias or deprecated tag with its canonical tag. It refuses an unknown tag, note text with a blank line or its own trailing tags, and a result that `scripts/notes.py` would reject. Add `--check` to print the note without writing it; run again, it changes nothing.
4. When an agent writes a note rather than the author, pass `--agent-written`, which adds `#agent-written` alongside its other tags; apply this going forward and do not retag older notes. `todo` alone is a valid tag.
5. Give every new `todo` a date, written as `31 October 2026` or `2026-10-31`, and a done-condition phrased `done when <observable outcome>`. `scripts/add_note.py` and `scripts/validate.py` reject a `#todo` note missing either one under a heading dated on or after 2026-10-03; notes under older headings are exempt.
6. Close a `todo` as either resolved or dropped, or park it, without rewriting the older note's text. Each closing note is a new dated note, added with `scripts/add_note.py`.
   - **Resolved** means it was answered. Record the answer where it lives (add a `resolves` link to the note on the answering visual, media item or blog post, see [Link related items](../reference/links.md), or add a new dated note that says what resolved it), or add a dated closing note that lists the resolved items, each with its answer or a link to it.
   - **Dropped** means it was abandoned without an answer. Add a dated closing note that lists each dropped item as `Dropped: <item> - <one-line reason>`. Never call an abandoned todo resolved.
   - **Parked** means paused until a set date, neither resolved nor dropped. Add a dated note that starts `Parked until <date>: <item>`, with the reason, and tag it `#parked`. On the resume date, add a new dated `#todo` for it or drop it.
   - Unless a `resolves` link closes it, remove only the `#todo` tag from each original, leaving its text unchanged. The Open questions page shows the result. Apply this going forward; do not re-label todos closed before this rule.
7. Blank lines separate notes, and trailing hashtags become filters rather than displayed prose (use hyphens for multi-word tags). The build publishes newest-first, with stable links such as `notes.html#2026-09-24`.
8. Run [Stage A](../verify.md#stage-a-pre-deploy). Follow [Deploy generated files](deploy.md) when the request includes publication.

Principles: [Preserve user content](../principles/preserve-user-content.md) and [Minimal diff scope](../principles/minimal-diff-scope.md).
