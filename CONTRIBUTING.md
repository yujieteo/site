# Contributing

1. Edit sources under `data/`, `scripts/`, `templates/`, `static/`, `schema/`, `visuals/`, or `tests/`. Never hand-edit `site/`; it is regenerated by `scripts/build.py` and ignored by Git.
2. Pick the matching playbook from [SKILLS.md](SKILLS.md); it lists the exact steps for each kind of change. A public visualization changes in its folder of yujieteo/visuals, and the site builds it from there ([add-visualization.md](skills/playbooks/add-visualization.md)).
3. Before opening a pull request, run the commands in [README.md](README.md#build) and [README.md](README.md#test). Commit only the sources: `site/` is never committed, so independent pull requests do not conflict on generated pages, and CI builds it fresh.
4. Keep the diff scoped to the request, and never commit credentials, hostnames, or private paths.
