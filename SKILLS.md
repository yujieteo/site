## Rules for every task

Each rule is owned by the file it links to; read that file for the detail.

1. **Sources only.** `site/` is generated by `scripts/build.py`, ignored by Git and never committed or edited. Each externally built visualization is pinned by commit in `data/visuals/<slug>.pin`. See [README.md](README.md#build).
2. **Layout.** Content lives in `data/`; each visualization lives in its own folder `visuals/<slug>/`, usually a port of its standalone `yujieteo/<slug>` repository where it is built and tested, with a catalogue stub `data/visuals/<slug>.yaml`. Shared templates live in `templates/`: the page shell `templates/base.html`, and the beamdswitch report template `templates/beamdswitch.js` with its skeleton `templates/beamdswitch-report.md`, which every narrated report copies unchanged. See [README.md](README.md#adding-and-changing-content) and [add-visualization.md](skills/playbooks/add-visualization.md).
3. **Notes stay in one file.** Every note goes in `data/notes.md`; never split it, and land notes changes one at a time. See [add-note.md](skills/playbooks/add-note.md).
4. **Never hand-merge generated files.** On a conflict in a generated file, take either side and regenerate it from the merged sources. See [generated-files-are-read-only.md](skills/principles/generated-files-are-read-only.md).
5. **Tests.** Python `unittest` (needs `VISUALS_REPO`) and Node's built-in `node --test`, run and timed by `scripts/run_tests.py`; never add Vitest, Jest, a `package.json` or another test framework. Visual tests follow three-layer ownership: model tests in the visualization's repository, technical browser E2E in a dedicated E2E repository (pending; the visualization's repository stands in until it exists), and only site integration here. Site tests stay cheap and every added one is timed. See [README.md](README.md#test), [add-visualization.md](skills/playbooks/add-visualization.md#end-to-end-testing-and-the-two-pipeline-runs) and [Site test cost](skills/playbooks/add-visualization.md#site-test-cost).
6. **Use the tool's own numbers.** Where a page or script computes a value, quote its output; do not re-derive it by hand.
7. **Scope.** Do what was asked and nothing more: no unrequested features, refactors or content edits. See [minimal-diff-scope.md](skills/principles/minimal-diff-scope.md) and [preserve-user-content.md](skills/principles/preserve-user-content.md).
8. **No secrets, no server config.** Never commit hostnames, credentials or private paths, and never change the web server's configuration. See [no-secrets-in-repo.md](skills/principles/no-secrets-in-repo.md) and [atomic-safe-deploy.md](skills/principles/atomic-safe-deploy.md).
9. **Committed is not done.** A task is done when [Stage A](skills/verify.md#stage-a-pre-deploy) passes and the pull request is open, or, for a deploy, when [Stage B](skills/verify-post-deploy.md) passes. GitHub runs no checks on a pull request with merge conflicts: rebase it rather than wait for CI.
10. **Review by risk.** Data-only changes and straight visualization ports take the fast path: Stage A, then a plain pull request without the no-mistakes pipeline, landed on `main` only after its CI passes on that commit; never push one to `main` red or untested. Anything touching site code, templates, scripts, tests, CI or deploy keeps the full pipeline. The diff decides; see [Review tier](skills/verify.md#review-tier).
