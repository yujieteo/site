## Rules for every task

Each rule is owned by the file it links to; read that file for the detail.

1. **Sources only.** `site/` is generated by `scripts/build.py`, ignored by Git and never committed or edited. Public visualizations are built from the yujieteo/visuals checkout (`VISUALS_REPO`, else a sibling of this or the primary checkout) as it is checked out, and the build prints the path, source and commit it read. See [README.md](README.md#build).
2. **Layout.** Content lives in `data/`. Each public visualization is a folder `viz/<slug>/` of yujieteo/visuals, with its catalogue entry in its `visual.json`; only the private `beamdswitch` and `connes-qft` live here, in `visuals/<slug>/` with a catalogue stub `data/visuals/<slug>.yaml`. Shared templates live in `templates/`: the page shell `templates/base.html`, and the beamdswitch report template `templates/beamdswitch.js` with its skeleton `templates/beamdswitch-report.md`, which every narrated report copies unchanged. See [README.md](README.md#adding-and-changing-content) and [add-visualization.md](skills/playbooks/add-visualization.md).
3. **Notes stay in one file.** Every note goes in `data/notes.md`; never split it, and land notes changes one at a time. See [add-note.md](skills/playbooks/add-note.md).
4. **Never hand-merge generated files.** `site/` is untracked, so it never conflicts; a conflict under `site/` means the branch committed build output, which you remove rather than resolve. On a conflict in a committed generated file, take either side and regenerate it from the merged sources. See [generated-files-are-read-only.md](skills/principles/generated-files-are-read-only.md).
5. **Tests.** Python `unittest` (needs the visuals checkout; see the build order in the README) and Node's built-in `node --test`, run and timed by `scripts/run_tests.py`; never add Vitest, Jest or another test framework, and tests need no installed packages; `package.json` exists only to pin the type-check tooling (`npm ci && npm run typecheck`). Visual tests follow three-layer ownership: model and page tests in the visualization's folder in yujieteo/visuals, technical browser E2E checks pointed at the artifact, and only site integration here. Site tests stay cheap and every added one is timed. See [README.md](README.md#test), [Test ownership](skills/playbooks/add-visualization.md#test-ownership) and [Site test cost](skills/playbooks/add-visualization.md#site-test-cost).
6. **Use the tool's own numbers.** Where a page or script computes a value, quote its output; do not re-derive it by hand.
7. **Scope.** Do what was asked and nothing more: no unrequested features, refactors or content edits. See [minimal-diff-scope.md](skills/principles/minimal-diff-scope.md) and [preserve-user-content.md](skills/principles/preserve-user-content.md).
8. **No secrets, no server config.** Never commit hostnames, credentials or private paths, and never change the web server's configuration. See [no-secrets-in-repo.md](skills/principles/no-secrets-in-repo.md) and [atomic-safe-deploy.md](skills/principles/atomic-safe-deploy.md).
9. **Committed is not done.** A task is done when [Stage A](skills/verify.md#stage-a-pre-deploy) passes and the pull request is open, or, for a deploy, when [Stage B](skills/verify-post-deploy.md) passes. GitHub runs no checks on a pull request with merge conflicts: rebase it rather than wait for CI.
10. **Review by risk.** Data-only changes and straight copies of an upstream private visualization take the fast path: Stage A, then a plain pull request without the no-mistakes pipeline, landed on `main` only after its CI passes on that commit; never push one to `main` red or untested. Anything touching site code, templates, scripts, tests, CI or deploy keeps the full pipeline. The diff decides; see [Review tier](skills/verify.md#review-tier).
